# Task10 native 120 Hz PBD producer adaptation — 2026-10-10

This record tracks the task-specific adaptation of the frozen Task10 producer
from 240 Hz to native 120 Hz for Isaac Sim 4.1 and 4.5, with scene position
iterations fixed to 64/64. **The current frozen revision16 passes producer static
cold-start qualification on both runtimes for 30 simulated seconds each.**
Full Scenario Forge titration, constrained VR motion and final video acceptance
remain downstream checks and are not claimed here.
The previous [240 Hz producer record](2026-10-09-task10-pbd-producer.md), source
scene, and old frozen outputs remain historical evidence and are not rewritten.

## Producer interface and acceptance contracts

`scripts/task10_pbd_producer.py` now exposes:

| Argument | Contract |
| --- | --- |
| `--physics-hz` | Positive integer native scene frequency; historical default remains 240. Native-120 work must specify 120. |
| `--baseline-snapshot` | Mutually exclusive with `--source`; verify all inventory hashes and exact membership before copying the frozen package. Reject an existing output or an output inside the baseline. |
| `--system-overrides` | JSON mapping Source, Receiver, Falling or DeadPrecharge to supported positive finite physical scalars. |
| `--repair-clamp` | Replace the filled clamp proxy and clip solid pads outside the original outer glass. |
| `--refine-source-wall` | Add short convex side-wall cells from the existing Source cavity profile. |
| `--refine-receiver-wall` | Add task-specific exact-profile Receiver wall cells and an original-plane floor disk; used in revision16. |
| `--settled-state`, `--settling-report` | Paired measured-state import on the source-build route; baseline derivation rejects these flags. |

Allowed override keys are `fluidRestOffset`, `restOffset`, `solidRestOffset`,
`contactOffset`, `particleContactOffset`, `maxVelocity`, and
`maxDepenetrationVelocity`. Unsupported keys, nonfinite values, booleans, or
nonpositive values fail validation. Scalar experimentation is not qualification.

A new `runtime_configuration_sha256` hashes canonical sorted compact JSON of
`physics_configuration_sha256` and the complete `runtime_contract`. It therefore
binds dt, scene frequency, iteration bounds and declared capacity settings to
the physical configuration. A nominal 120 Hz candidate cannot reuse a 240 Hz
runtime signature. Baseline derivation clears the old settling observation,
sets both runtime qualifications to `not_run`, and records
`frozen_baseline_seed_re_equilibration_required`; copied reports remain historical.

At native 120 Hz, measured-state import requires
`actual_step_dt_evidence.source = native_physics_step_callback`, a positive
integer callback count, finite minimum/maximum/target/World dt, accumulated
simulation time, and PhysicsScene rate. Each dt must match 1/120 within 1e-8 s;
summed time must match count times target within count times that tolerance.
A low-level `simulate(dt)` argument or nominal manifest rate alone does not
satisfy this contract. Physical signature, runtime signature, state hash,
particle counts, full-run containment and tail surface bounds must also match.

Example seed derivation, requiring a new output directory:

```bash
python scripts/task10_pbd_producer.py \
  --baseline-snapshot outputs/task10_pbd_20261009/snapshots/prebalanced_06 \
  --out outputs/task10_pbd_120hz_20261010/candidates/NEW_REVISION \
  --physics-hz 120
```

Lossless prebalance means retaining every measured particle and velocity, without
clipping, deletion, selective relocation or zeroing velocities. Re-expression
under the original container placement uses one rigid affine map for all points
and its rotation for velocities. Counts and total mass stay fixed. A measured
state from an unqualified investigation may seed further settling, but it is not
a settling certificate and cannot be handed off as a qualified initial state.
Changed parameters require new observations and subsequent cold validation.

## Collision investigation and decisions

proxies intruding into the 5 mm-radius fluid bore, with point-in-solid witnesses
and before/after bounds. The solid `single_clamp_proxy` filled the negative-X

three boxes following the visible C-frame and four convex clipped pads. Pad
clipping uses the 6 mm outer-glass tangent planes, retaining approximately
80.45% of each pad and at least 1 mm clearance from the fluid cavity. All seven
replacement contacts remain enabled. There is no fluid collision filtering or
change to visible geometry or source poses.

candidate adds 1,024 normalized convex side-wall cells from the same existing
Source inner profile: maximum axial cell length 20 mm, 32 angular sectors,
maximum polygon chord inset about 25.1 µm, and 3 mm outward thickness. The SDF
is retained, with no new interior floor. This is a task-specific contact
refinement, with no robot grasp-clearance claim.

The first wall-refinement run, wall04, exhausted GPU aggregate pair capacity.
PhysX explicitly reported that `foundLostAggregatePairsCapacity` needed at least
1,354 or interactions would be missed. **All wall04 physical observations and
its state are invalid for qualification or physical conclusions.** Its report
remains diagnostic evidence even though its top-level status says `observed`.

Wall05 retains that geometry and raises both found/lost and total aggregate-pair
capacities to 8,192. These are explicit runtime-contract requirements, not hidden
local tuning. Its live scene readback confirms both capacities and the 64/64
